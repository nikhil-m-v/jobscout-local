## Concrete failure and fix

Entering a saved-job list item with Narrator read the entire card as one long,
concatenated accessible name: stage, source, dates, URL, snapshot, private note and
button text preceded the heading. This made heading navigation unnecessarily
verbose. Each item now uses `aria-labelledby` pointing to its own existing job
heading. Details and editor controls remain separately exposed; no content,
storage, provider boundary, dependency or engine behavior changes.

The rebuilt installed package exposes a title-only list-item name. Narrator scan
navigation now says “Enter List, SYNTHETIC CRASH RECOVERY JOB, heading level 2”
without the preceding card dump. Pre-fix and post-fix speech-recap captures are
retained separately. A two-record rendering regression checks distinct heading
references and retained note/editor content. All 168 frontend tests pass, as do
typecheck/frontend build and release native/NSIS packaging. Full engine/harness
suites and hosted CI were not rerun or newly claimed for this markup-only fix.
