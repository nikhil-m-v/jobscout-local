# Bounded Tavily discovery adapter

The first discovery implementation is deliberately isolated from HTTP routes and UI. `domain/discovery.py` defines a small replaceable async provider contract and immutable query/candidate results. `adapters/tavily_search.py` imports no profile, database, secret-store, document or model implementation. The caller will supply the credential from the existing vault only after explicit confirmation. This increment does not register a search route, enable dispatch, or make an automatic/live provider call.

The adapter accepts raw controlled criteria, revalidates them and rebuilds the version-1 query immediately before dispatch. The supplied reviewed query must exactly match this reconstructed query; it is compared locally and never serialized. Arbitrary caller queries, endpoints, extra fields and options cannot reach the provider. This comparison prevents stale query dispatch but is not itself evidence of a human confirmation. The next API/UI increment must enforce fresh provider/query review and a separate Send action, reject duplicate work and invalidate late results.

The fixed request is one HTTPS POST to `https://api.tavily.com/search`. Authentication is only in Authorization; JSON contains the constructed query and fixed basic/general/ten-result settings. Automatic parameter selection, answers, raw content, images and favicons are explicitly disabled. The endpoint and documented parameters were checked against [Tavily's official search reference](https://docs.tavily.com/documentation/api-reference/endpoint/search). No SDK or dependency is added. Provider credits may be consumed; a timeout/cancellation does not undo a sent request. There are no retries, pagination or follow-up requests.

Transport verifies TLS, ignores environment proxy/netrc/certificate overrides, disables redirects, permits one connection, and creates a fresh client per search so response cookies are not reused. Network work is bounded by ten-second phase timeouts and twenty seconds total. Error bodies are not read or echoed. Successful JSON must use identity encoding; declared and streamed bytes are capped at 256 KiB. Duplicate keys, unsupported content types/encoding, malformed JSON, oversized or invalid result shapes fail with fixed codes. HTTP auth, quota/rate limits, network and timeout failures have distinct fixed codes. Async cancellation closes the response/client and propagates cancellation to its caller.

Only title, HTTPS URL and snippet survive into the immutable candidate list. At most ten records are accepted; title/URL/snippet limits are 512/2048/16384 characters. Exact URLs after fragment removal are deduplicated. Credentials in selected response fields cause rejection. Provider answer, score, echoed query, raw content, images and all other metadata are discarded. Results remain untrusted plain text, including any apparent instructions; there is no interpreter, HTML renderer, link opener, scraper, DNS lookup or embedded-resource loading in the adapter.

URLs reject userinfo, whitespace/control/backslash characters, non-HTTPS schemes, nonstandard ports, local/private IPs and conventional local/single-label/numeric DNS aliases. This is a conservative syntax boundary, not verification of ownership or protection against DNS rebinding. A future external-open action needs its own explicit disclosure and validation; no result link is opened here. These are web search candidates, not verified vacancies or guaranteed preference matches. Availability, freshness, broader canonicalization, job-specific filters, 30–50-result discovery and local ranking remain later work.

Evidence: 68 new adapter tests and 210 total engine tests pass. Captured synthetic requests verify exact method/URL/body/header allowlists and no private markers or credential in JSON/logs. Cases cover arbitrary/private fields, stale reviews, invalid keys, status errors, redirects, TLS/proxy/cookie behavior, malicious text/URLs, duplicates, empty results, byte/schema limits, diagnostic suppression, timeout and cancellation cleanup. Existing route tests continue to verify that no `/api/v1/search` dispatch route exists. No real provider key, live Tavily request or UI/native verification is claimed. The full application privacy gate remains open until dispatch confirmation and safe result rendering are integrated and verified.
