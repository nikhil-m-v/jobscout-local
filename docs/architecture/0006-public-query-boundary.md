# Authoritative public query construction

The engine owns the criteria-to-query boundary in `domain/search.py`. The frontend catalog is a convenience, not authority. Engine validation requires exactly role, region, seniority, arrangement and skills; values must be exact supported identifiers. Skills are unique, limited to five and sorted by identifier. A frozen snapshot is returned. Query construction always validates raw input again and emits engine-owned labels only, in role/jobs/region/seniority/arrangement/skills order. `any` preferences emit no term. Version 1 uses plain space-separated terms; these are search hints, not guaranteed provider filters.

`POST /api/v1/search/preview` requires the existing app bearer session. It accepts application/json, reads at most 4096 bytes with a five-second body timeout, rejects duplicate JSON keys and returns a fixed invalid_search_criteria error without input echo. Responses use Cache-Control: no-store. Valid responses contain query, query_version, provider=null and dispatch_available=false. There is no query retention, profile access, provider request, credential use or dispatch route. This endpoint is local preview construction, not permission to send a search.

The search domain module imports only standard dataclass/immutable-map facilities and has no profile, database, model or HTTP dependencies. Frontend/engine catalog identifiers are cross-checked by a test; expand both catalogs deliberately. No arbitrary endpoint, query, employer, contact, URL, filename or model output field is accepted.

The next increment exposes this engine-generated query in the browser and native UI with stale-preview invalidation and disclosure. When a provider is selected, the transport must use a fixed reviewed HTTPS endpoint allowlist, minimal headers, disabled redirects and bounded requests. It must call this boundary immediately before dispatch and ensure the displayed query matches the request. Provider consent and captured-request privacy verification remain required. Endpoint/redirect protections are not claimed by a preview-only endpoint with no network client.

Evidence: 24 synthetic search tests and 69 total engine tests pass, including catalog parity, deterministic ordering, malformed/bounded JSON, authentication, fixed errors, forbidden profile access and HTTP calls. Frontend production typecheck/build and three criteria tests pass. No dependency change. Native packaging and UI integration are not part of this increment.

## UI preview continuation

Discover now calls this endpoint through the fixed development proxy route or the native search_preview command. Both forward only validated criteria to the local engine. The native command uses the existing authenticated, redirect-disabled local client and a ten-second timeout; browser requests use no-store, omitted browser credentials, redirect rejection and a ten-second timeout.

Preparation and review are separate explicit actions. No query is synthesized in the frontend. The response must match the supported version and explicitly report no provider/no dispatch; unknown fields or unsupported responses fail closed. Query text renders as selectable plain text. Offline state leaves controls editable but disables preparation. Loading, cancellation and fixed error/retry controls are available.

Application-level preview state survives page navigation. Criteria changes synchronously clear query/review/error, abort browser requests and advance a generation counter. Late native or browser responses cannot restore stale state, even when cancellation is ignored by the transport. Disconnect and unmount invalidate pending/results too. Native cancellation discards results; it does not stop an already running bounded local command. Reload/exit clears all criteria/preview state. Review does not authorize online dispatch.

Continuation evidence: frontend production build/typecheck, all 13 frontend tests and offline release Cargo check passed. Browser against the real local engine verified preview generation, explicit review, skill-change invalidation, updated-role query, navigation retention and reload reset; dark compact layout was inspected. Native runtime interaction/new installer, light theme and full width-range checks remain unverified.
