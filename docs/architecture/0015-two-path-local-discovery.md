# Two discovery paths with local assistance

Target references amended 2026-10-10 to the current 10–20 suitable-job requirement. Recorded measurements and trial outcomes remain historical.
Date: 2026-10-04. Amendment to the existing assisted-discovery design and roadmap increments 16–17; optional LLM extension stays in 27–30.

Previously a resume affected extraction/review/storage only. Both entry paths used manual criteria and the same default query. Add a functional deterministic baseline without requiring a model download.

The resume path requires reviewed text. `Generate suggested search` requests local category analysis and opens the query page directly if a supported role is detected. A short category summary identifies role/skill mentions and explains their uncertainty. Users may correct the public categories before preparing a fresh query. If no supported role is found, show that limitation and require manual category selection. Without a resume, start with preferences/optional skills. Explicit skip clears derived criteria, query, results and analysis; it excludes any uploaded/saved text from subsequent search assistance. Resume text may remain in the existing draft for later review. Uploading or saving never sends a provider request.

`POST /api/v1/assistance` accepts exactly reviewed text and at most ten title/snippet pairs, behind session authentication, bounded/time-limited JSON parsing, duplicate-key rejection, thread-pool execution, fixed errors and no-store responses. There is no network, model, database, vault, filename or URL access in the assistance domain. Browser proxy/native bridges expose only this fixed local endpoint. Text remains bounded by the existing 200,000-character import contract; no new dependency or durable analysis record is introduced.

Whole-term role/skill aliases map to the existing catalogs; Java does not match JavaScript and SQL does not match NoSQL. Choose the first supported role mention and first five skill categories as suggestions. Do not infer preferred geography/work mode/seniority from private text, nor treat a mention as proof of expertise or current career intent. Unsupported, historical, negated and incidental terms can still confuse the baseline; the summary, correction controls and manual fallback are required. Private text or LLM prose cannot be copied into an outbound query. The independent public criteria boundary still reconstructs the exact query and dispatch still requires explicit query-face confirmation.

After retrieval, the engine scans title/snippet category mentions and computes shared resume/job skill categories locally. The UI only orders the returned evidence by count, retaining provider-order ties, and shows shared category labels alongside the source snippet. This is evidence of word/category overlap, not a fit score, verified job requirement or explanation of career history. Manual searches retain provider order. Local Results filters cover role, broad region, arrangement, seniority and skill mentions. Missing categories remain visible by default with an explicit exclude-unknown choice; filters operate only on the current bounded pool and do not search again. No vacancy or location verification is claimed. Different resumes may share a query; per-candidate uniqueness is not promised.

Analysis is asynchronous with cancel/retry/manual fallback. Generation guards ignore late replies on edits, cancellation, mode switching and disconnection. Resume edits/replacement/discard invalidate assisted criteria/preview/results and require review again. Results remain readable during local analysis; failures preserve provider order. Resetting filters sends nothing online. Existing semantic glass tokens, native selects, keyboard focus and reduced-motion controls are reused.

Setup: no new credential, runtime, permission or model is required; deterministic assistance is the default. Drafts/analysis are session-only, saved text retains its existing explicit storage/deletion contract. Upgrade by rebuilding/restarting engine, frontend and native bridge together; no database migration. Older installed/running copies require reopening/updating. A future optional LLM must use a selected local model, licence/resource-reviewed setup, bounded generation, cancellation and deterministic recovery. It may summarise privately and suggest validated catalog IDs, never supply provider-query prose. That extension remains unimplemented until its existing roadmap prerequisites pass.

Evidence: synthetic profiles demonstrate different controlled queries and different shared-skill ordering for the same returned pool. Captured end-to-end local-analysis/preview/search tests exclude distinctive private markers from provider requests and verify analysis touches no profile storage. Tests cover unsupported roles, input bounds, strict response catalogs, stale replies, filters/unknowns and separate query/manual page rendering. Native interaction, visual QA, live-provider relevance, richer evidence and the 10–20-job shortlist remain separate completion gates.
